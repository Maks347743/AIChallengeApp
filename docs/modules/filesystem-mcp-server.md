# Filesystem MCP Server

## Обзор

Filesystem MCP Server предоставляет инструменты для работы с файловой системой проекта через Model Context Protocol (MCP). Сервер работает на порту 3004 и предоставляет безопасный доступ к файлам проекта с защитой от выхода за пределы корневой директории.

## Архитектура

### Основные компоненты

1. **Main.kt** - точка входа сервера
2. **FilesystemToolRegistry** - реестр инструментов
3. **FilesystemMcpRequestHandler** - обработчик MCP запросов
4. **FilesystemToolHandler** - базовый интерфейс для инструментов
5. **PathUtils** - утилиты для безопасной работы с путями

### Инструменты

Сервер предоставляет 5 основных инструментов:

## 1. read_file

**Описание:** Читает полное текстовое содержимое файла в пределах директории проекта.

**Параметры:**
- `path` (обязательный) - относительный путь к файлу от корня проекта

**Пример использования:**
```json
{
  "path": "app/src/main/java/com/example/MainActivity.kt"
}
```

**Особенности:**
- Ограничение на размер файла: 50,000 символов (при превышении добавляется суффикс `[...truncated]`)
- Автоматически определяет бинарные файлы и не пытается их читать
- Защита от выхода за пределы корневой директории

## 2. list_files

**Описание:** Выводит список файлов и директорий в проекте. По умолчанию пропускает сгенерированные директории (build, .gradle, .idea, .git).

**Параметры:**
- `path` (необязательный) - относительный путь к директории от корня проекта (по умолчанию ".")
- `pattern` (необязательный) - glob-паттерн для фильтрации результатов (например, `**/*.kt`)
- `max_depth` (необязательный) - максимальная глубина обхода директорий (по умолчанию 6)

**Примеры использования:**
```json
{
  "path": "feature/chat",
  "pattern": "**/*.kt",
  "max_depth": 3
}
```

**Особенности:**
- Ограничение на количество записей: 300 (при превышении добавляется суффикс `[...results truncated at 300 entries]`)
- Автоматически исключает системные директории: `build`, `.gradle`, `.idea`, `.git`, `.kotlin`, `node_modules`, `__pycache__`, `.DS_Store`
- Поддержка glob-паттернов для фильтрации файлов

## 3. search_in_files

**Описание:** Ищет текстовый запрос в содержимом файлов. Возвращает совпадающие строки с путем к файлу и номером строки.

**Параметры:**
- `query` (обязательный) - текст для поиска (регистронезависимый)
- `path` (необязательный) - относительный путь для поиска (по умолчанию ".")
- `filePattern` (необязательный) - glob-паттерн для фильтрации имен файлов (например, `*.kt`)

**Пример использования:**
```json
{
  "query": "ChatViewModel",
  "path": "feature/chat",
  "filePattern": "*.kt"
}
```

**Особенности:**
- Ограничение на количество совпадений: 200
- Максимальный размер файла: 1 МБ
- Автоматически пропускает бинарные файлы (расширения: `.class`, `.jar`, `.png`, `.jpg`, и т.д.)
- Поддержка поиска в одном файле или рекурсивно в директории

## 4. write_file

**Описание:** Записывает (создает или перезаписывает) файл по указанному пути с предоставленным содержимым. Возвращает unified diff изменений.

**Параметры:**
- `path` (обязательный) - относительный путь к файлу от корня проекта
- `content` (обязательный) - содержимое для записи в файл

**Пример использования:**
```json
{
  "path": "docs/new-feature.md",
  "content": "# New Feature\n\nThis is a new documentation file."
}
```

**Особенности:**
- Автоматически создает родительские директории при необходимости
- Возвращает unified diff в формате Git для наглядного отображения изменений
- Для больших файлов (>500 строк) использует упрощенный алгоритм diff

## 5. create_file

**Описание:** Создает новый файл с заданным содержимым. Завершается ошибкой, если файл уже существует.

**Параметры:**
- `path` (обязательный) - относительный путь к новому файлу от корня проекта
- `content` (обязательный) - содержимое для записи в новый файл

**Пример использования:**
```json
{
  "path": "src/main/java/com/example/NewClass.kt",
  "content": "package com.example\n\nclass NewClass {\n    // Implementation\n}"
}
```

**Особенности:**
- Проверяет существование файла перед созданием
- Автоматически создает родительские директории
- Возвращает размер созданного файла в байтах

## Безопасность

### Защита от выхода за пределы директории

Все инструменты используют функцию `sandboxedPath` из `PathUtils.kt`, которая:
1. Преобразует пути в каноническую форму
2. Проверяет, что целевой путь находится внутри корневой директории проекта
3. Выбрасывает исключение `IllegalArgumentException` при попытке выхода за пределы

### Ограничения ресурсов

1. **read_file**: ограничение 50,000 символов
2. **list_files**: ограничение 300 записей, глубина обхода 6 уровней
3. **search_in_files**: ограничение 200 совпадений, размер файла 1 МБ
4. **write_file**: ограничение на вычисление diff для файлов >500 строк

## Запуск сервера

### Параметры командной строки
```bash
--project-dir <путь>  # Указать корневую директорию проекта (по умолчанию текущая директория)
```

### Пример запуска
```bash
java -jar filesystem-mcp-server.jar --project-dir /path/to/android/project
```

## Интеграция с Android приложением

### Конфигурация в build.gradle
```kotlin
// В BuildConfig
const val FILESYSTEM_MCP_URL = "http://localhost:3004"
```

### Использование в ChatViewModel
Инструменты filesystem MCP автоматически доступны через `McpToolClientManager` и могут быть вызваны из чата.

### Пример вызова из AI
```
Пожалуйста, прочитай файл app/src/main/AndroidManifest.xml
```

AI может использовать инструменты через MCP протокол:
```json
{
  "tool": "read_file",
  "arguments": {
    "path": "app/src/main/AndroidManifest.xml"
  }
}
```

## Логирование

Сервер использует стандартное логирование Ktor. В режиме отладки можно увидеть детальные логи HTTP запросов.

## Обработка ошибок

Все инструменты возвращают структурированные ошибки в формате MCP:
- `isError: true` - флаг ошибки
- `content.text` - описание ошибки

Типичные ошибки:
- `File not found` - файл не существует
- `Not a file/directory` - путь указывает не на файл/директорию
- `Invalid path` - попытка выхода за пределы корневой директории
- `Binary file, cannot read as text` - попытка чтения бинарного файла

## Расширение функциональности

Для добавления нового инструмента:
1. Создать класс, реализующий `FilesystemToolHandler`
2. Реализовать методы `name`, `description`, `inputSchema`, `execute`
3. Добавить инструмент в список в `Main.kt`
4. Обновить документацию
